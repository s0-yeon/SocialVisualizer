# 제한사항 및 재현성 안내

본 문서는 SocialVisualizer의 **Llama 파인튜닝 및 데이터 구축 과정**에서 발생하는 **제한사항**과 **재현성** 관련 사항에 대하여 설명한다.

---

## 1. Query SFT 데이터 구축 스크립트는 재구성본

`sft_data_construction/query/`에 포함된 8개 스크립트는 개발 당시 실행에 사용한 원본 코드가 아니라, 개발 과정에서 분석·기록해둔 알고리즘 설명을 기반으로 재구성한 코드이다.

실제 학습에 사용된 최종 SFT 데이터는 학습 서버에 별도로 보관되어 있으며, 본 저장소에는 포함하지 않았다.

따라서 해당 스크립트를 실행하여 생성되는 데이터와 실제 학습에 사용된 데이터가 완전히 동일하지 않을 수 있다.

자세한 데이터 구축 과정은 `sft_data_construction/query/README.md`를 참고.

---

## 2. 메신저 도메인의 extract_graph SFT 데이터는 근사 매칭을 사용

이메일 데이터의 경우 GraphRAG 캐시 응답에 원본 메일의 고유 ID가 포함되어 있어 원본 데이터와의 매칭이 가능하다.

반면 메신저 청크에는 안정적인 고유 ID가 없어 `채팅방 이름 + 날짜`를 기반으로 원본 청크와 GraphRAG 결과를 매칭했다.

이 방식에서는 동일한 날짜에 여러 개의 청크가 생성되는 경우 일부 데이터를 정확하게 구분하지 못할 수 있다.

매칭 방식과 관련된 세부 내용은 `sft_data_construction/indexing/extract_graph_matching/`을 참고.

---

## 3. 원본 학습 데이터는 저장소에 포함하지 않음

모델 학습에 사용한 원본 합성 이메일·메신저 데이터와 일부 중간 산출물은 저장소에 포함하지 않았다.

학습 데이터는 실제 개인 데이터가 아닌 합성 데이터로 구성되었다.

따라서 공개 저장소에서는 데이터 원문 대신 데이터 구축 과정과 관련 스크립트를 제공한다.

---

## 4. 개발 환경과 재현 환경의 차이

파인튜닝과 모델 서빙은 GPU, CUDA, PyTorch, LLaMA-Factory, vLLM 등의 실행 환경에 영향을 받을 수 있다.

특히 다음 항목은 실행 환경에 따라 변경될 수 있다.

- GPU 종류 및 VRAM
- CUDA 버전
- Python 및 주요 라이브러리 버전
- `max_model_len`
- `gpu_memory_utilization`
- batch size
- 학습 설정

따라서 다른 환경에서 학습 및 서빙 결과가 완전히 동일하지 않을 수 있다.

---

## 5. 개발 서버 전용 설정

`serving/gpu_server_ops.md`에는 개발 당시 사용한 GPU 번호, `/workspace/` 경로, tmux 세션 이름 및 포트 등의 환경 의존적인 설정이 포함되어 있다.

해당 문서는 개발 및 운영 참고용이며, 일반 사용자가 그대로 실행하는 것을 전제로 하지 않는다.

다른 환경에서는 GPU 번호, 모델 경로, 가상환경 경로, 포트 및 tmux 세션 등을 자신의 환경에 맞게 수정해야 한다.

---

## 6. eval/ QA 세트는 완전히 분리된 평가셋이 아님

`eval/`의 `Llama_mail_QA.xlsx`, `Llama_messenger_QA.xlsx`는 `query` adapter의 `local_search` SFT 학습 데이터 원본이며, 143문항 전체가 train/val로 분할되어 실제 학습(및 체크포인트 선택)에 사용됐다.

따라서 학습에 사용되지 않은 독립적인 held-out 벤치마크가 아니라는 점에 유의해야 한다.
